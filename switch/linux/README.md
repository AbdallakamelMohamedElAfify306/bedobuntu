# Reboot to Android launcher (Phosh 0.38, Pixel 7 Pro / Ubuntu on slot b)
Files: omamobile-reboot-android (root helper, python3 only) · omamobile-reboot-android-gui (GTK3 dialog, zenity fallback) · .desktop · .svg icon ·
.sudoers (one command, one argument) · install.sh (generated by build.sh) · cmd-install.txt / cmd-verify.txt / cmd-dialog-test.txt / cmd-rollback.txt.
Flow: tap icon -> dialog (Cancel is default) -> `sudo -n omamobile-reboot-android apply` -> helper: refuses unless running slot is b; reads devinfo (must be DEVI 3.15);
backs up devinfo (8 KiB) to /root/devinfo-backups/; reads bBootLunEn through sysfs AND the UFS BSG node (must agree, must be 1 or 2);
writes bBootLunEn=1 (read back); unlocks ONLY the devinfo partition (BLKROSET), writes bytes 0x30..0x37 O_SYNC, re-locks, re-reads from the media (O_DIRECT) and compares;
any failure after the first write rolls both back and the phone does not reboot; success -> sync -> systemctl reboot.
Tested here: synthetic devinfo + fake LUN file (apply, idempotent re-apply, refusal on wrong slot/bad header/LUN=3, rollback when the devinfo write fails, restore),
and a real 4096-byte-sector loop block device for O_DIRECT read, BLKROSET (write refused while ro, allowed after), BLKFLSBUF, write+read-back.
NOT testable off the phone: the sysfs partition discovery, the UFS BSG write, the GTK rendering.
