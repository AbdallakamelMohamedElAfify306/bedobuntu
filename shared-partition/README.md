# shared-part: one ext4 partition shared by Android (Magisk) and Ubuntu on the Pixel 7 Pro

## Design (decisions and why)
* **GPT**: add a 33rd entry `shared` in the free tail (after userdata), type GUID copied from the `ubuntu` entry (the layout ABL already accepted), 1 MiB aligned, 16 MiB gap after userdata, ends 1 MiB before last usable: sectors **25957120..31195903** (4 KiB sectors) = 20464 MiB. Entry array room is 128 entries in both copies (4 reserved sectors, first usable 6), so the array never has to move; first/last usable, backup LBA, disk GUID and all 32 existing entries stay byte-identical. Raw edit (python stdlib) exactly like the proven 31->32 edit, rehearsed in memory, written backup-copy-first, read back, verified with sgdisk -v.
* **Two-step, canary first**: `grow` (32->33 entries, new entry empty) -> reboot Ubuntu, `fastboot getvar all`, boot Android -> only then `create`. 33 entries = 4224 bytes: the array now spans TWO 4 KiB sectors (32 entries were exactly one sector), the one thing ABL has never seen; the canary tests exactly that. Android's own boot HAL (gs101 GptUtils.cpp, read in full) uses count*128 from the header, a `std::vector` and recomputes CRCs over count*128, so it is count-agnostic; it stops at the first nameless entry (ours is named and contiguous).
* **Filesystem = ext4** (not exFAT/f2fs): the Ubuntu kernel here has `# CONFIG_EXFAT_FS is not set` (kernel-out/.config), F2FS only as module, EXT4=y with POSIX ACL; Android GKI 6.1 has ext4 (+ACL), exFAT, vfat, f2fs built in. Only ext4 is in both. Created conservative (4 KiB blocks, journal kept, no orphan_file, no lazy features beyond itable init, label SHARED, reserved 0%).
* **Permissions**: ext4 keeps uid/gid, so exFAT-style uid= mounts are impossible. Root dir owner 0:1023 (media_rw) mode 2770 + POSIX ACL (access + default) granting group 1023 and Ubuntu uid 1000 rwx. The default ACL makes every new file/dir (made by Ubuntu, by Android's MediaProvider FUSE daemon, any owner) accessible to both regardless of umask. Android side mounts with `context=u:object_r:media_rw_data_file:s0` so every file is labelled correctly without xattrs.
* **Android visibility**: mount at `/data/adb/shared-part/mnt` (root-only path), then `mount -o bind` onto `/data/media/0/Shared` in the global namespace (`su -M`), only after the user unlocked once (names in /data/media/0 are FBE-encrypted before). That path is the lower fs of MediaProvider's FUSE daemon, so `/sdcard/Shared` shows it (FUSE passthrough, no sdcardfs on this kernel). The mount propagates through shared/slave propagation of /data; it is verified with a marker file through `/mnt/user/0/emulated/0/Shared`, and if not visible the same device is mounted inside MediaProvider's own mount namespace (`nsenter -t <pid> -m`, the documented fallback for Android 11+). UNVERIFIED on a device: the propagation behaviour on this exact build (CP3A.261005.002.A1); `once` reports it.
* **Ubuntu**: `shared-part.service` runs `/usr/local/sbin/shared-mount`: finds the partition by PARTNAME, checks ext4 label, `blockdev --setrw` on that one partition (the initramfs guard sets every partition outside its allowlist read-only on each boot and the allowlist is hard-coded to boot_b..., userdata, ubuntu; changing it means rebuilding vendor_kernel_boot_b, so it is NOT touched), `e2fsck -p`, mount `/mnt/shared`. udev rule UDISKS_IGNORE stops udisks double-mounting. The initramfs is unaffected by sda33: `find_root` only inspects partitions named ubuntu/userdata; `ufs_ro_pass` makes sda33 read-only; `ufs_unguarded` therefore stays empty and boot_arch does not stay in the initramfs.

## Risks (honest)
1. ABL/bootloader with 33 entries / 2-sector array: unknown, tested only by the canary (probability low; 31->32 and Android's HAL are fine). Tail risk as in split-plan-v2: if ABL rejected the table the phone could stop booting; restore needs Linux/fastboot partition flash. Mitigation: canary step, byte-exact backups on phone + Mac, `restore.sh` (verified here to restore the table byte for byte).
2. Any bootloader/factory-image flash that writes `partition:0` resets the GPT (loses entries 32+33 too, data stays).
3. Not encrypted: Ubuntu (unlocked) and anyone booting Ubuntu can read it.
4. Android 17 FUSE/mount-namespace behaviour not testable here; the scripts verify and log (`/data/adb/shared-part/log`).
5. Unclean switch between OSes: ext4 journal replays on next mount; Ubuntu also runs `e2fsck -p`.
6. Ubuntu helper uses uid 1000 `user`; other uids need `--uid N` at format time (or `setfacl` later).

## Files
* `diag.txt` read-only diagnostics (Ubuntu one-liner, Android variant)
* `shared-part-create.sh` (Ubuntu, bash; embeds `sp_engine.py`): check | backup | grow | create | format
* `shared-part-ubuntu.sh` (Ubuntu): install | uninstall | status
* `shared-part-android.sh` (Android, POSIX sh; also the service.d script): install | once | run | status | diag | umount | uninstall
* `shared-part-rollback.sh` (Ubuntu): soft | gpt [--to original|empty33]
* `STEPS.md` (Arabic user steps), `sp_engine.py`, `sp_diag.py`, `shared-part-create.template.sh` + `build.sh` (regenerates create.sh), `test/` (synthetic 4096-B-sector Pixel GPT on a loop device with real sgdisk 1.0.10; `test/run-tests.sh`, `test/test-log.txt`)
## Tested here / not tested
Tested: raw GPT edit + rollback on a synthetic disk (sgdisk -v clean, byte-identical restore), all STOP guards, sh -n/dash -n/shellcheck on all scripts, fs_ok superblock logic. NOT tested (no phone, no e2fsprogs on the box): mkfs/ACL/mount, systemd unit, Android mount/bind/FUSE visibility.
